## 3. Overall Architecture

Build the following hybrid AI architecture:

**User input → Speech-to-text or text input → Input normalization → Custom ML intent classifier → Confidence-based routing → Safe computer tool OR Gemini API → Response generation → UI and optional text-to-speech**

The system must use two complementary intelligence layers.

### Layer A: Custom local ML intent classifier

Train a real machine learning model using scikit-learn. It must classify user requests into supported intent categories and help decide which application component should handle them.

The model must be trained and evaluated using a proper dataset split. Save the trained artifact locally and load it for inference.

### Layer B: Gemini API

Use Gemini for:
- General knowledge questions
- Natural conversation
- Complex requests
- Reasoning and explanations
- Summarization
- Requests that the local intent classifier cannot confidently categorize
- Interpreting requests that need supported tool selection

Gemini must not directly execute computer operations. It may request an approved tool call, but the backend must validate the arguments and enforce permissions before execution.

### Routing policy

Implement a clear, testable routing policy.

- High-confidence, supported intents may be routed to the corresponding local tool.
- Ambiguous requests should be clarified or sent to Gemini when appropriate.
- Requests that require general reasoning should use Gemini.
- Low-confidence predictions must not trigger potentially dangerous actions.
- Safety checks must remain independent of classifier confidence.
- The assistant should explain when an operation is unsupported or requires confirmation.

Do not send every message to Gemini unnecessarily. Also, do not force every message through the local ML model if that would reduce reliability.

- Listing reminders

- Deleting reminders

Use a legitimate, supported search API or another documented integration. Keep credentials server-side and document any external service requirements.

### F. System control

Implement only explicitly approved, low-risk system operations.

For example, locking the workstation may be supported through a narrowly defined Windows integration.

Requirements:
- Validate every requested operation against an allowlist.
- Ask for confirmation before consequential actions.
- Never execute arbitrary PowerShell, CMD, Python, or shell text supplied by Gemini.
- Never disable security software or weaken Windows security.
- Never delete files, alter security settings, or perform destructive actions without explicit user authorization and appropriate confirmation.
